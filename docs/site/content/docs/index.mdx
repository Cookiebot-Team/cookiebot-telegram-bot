Cookiebot keeps a Telegram group habitable: it greets new members, screens
joiners, holds the group's rules, keeps sticker floods and drive-by image spam
under control, and carries a set of everyday tools. It speaks **English,
Portuguese and Spanish**, and Telegram is the entire interface — no account, no
dashboard.

## Build it

Cookiebot is being rebuilt in the open. **v2 is a rewrite that has to earn every
switch-over**: a feature moves only once its behaviour is captured as an
executable scenario and that scenario passes. Groups keep running on the current
release until then.

## How this site is built

Two kinds of page, and it is worth knowing which one you are reading.

**Measured** — the progress board, the header on every feature page, and the
command tables under *Commands* — are generated from the bot's own spec, alias
table and a real test run (`python scripts/cb.py docs-sync`). Nothing on them
is an opinion: a feature that claims to be done without a passing scenario is
reported as a finding, on the page, in amber.

**Written** — everything else. Intent, behaviour that must not change, and the
traps. The generator never touches it.

## The one rule

v1 compatibility is not negotiable. Groups are using the current release right
now, so a command that changes its name, its permissions or its reply is a
regression — however much nicer the new code is. Every ported feature carries a
behaviour contract and at least one scenario that would catch that.
