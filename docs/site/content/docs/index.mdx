Cookiebot is a Telegram group bot — moderation, captchas, group config, media
tools — serving real groups today on its v1 stack. **v2 is a rewrite that has
to earn every switch-over**: a feature moves only once its behaviour is
captured as an executable scenario and that scenario passes.

This site is where that is tracked, in public, with numbers nobody typed by
hand.

## How to read this site

Two kinds of page, and it is worth knowing which one you are on.

**Measured pages** — the progress board, and the header block on every feature
page — are generated from `scripts/spec.py` (the migration spec) and a real
test run, by `python scripts/cb.py docs-sync`. Nothing on them is an opinion.
A feature that claims `done` without a passing scenario is reported as a
finding, on the page, in amber.

**Written pages** — everything else, including the prose under each feature
header — are for humans, by humans. They explain intent, the v1 behaviour that
must survive, and the traps. The sync never touches them.

## The one rule

v1 compatibility is not negotiable. Groups are using the old bot right now, so
a command that changes its name, its permissions or its reply is a regression —
however much nicer the new code is. Every ported feature carries a behaviour
contract and at least one scenario that would catch that.
