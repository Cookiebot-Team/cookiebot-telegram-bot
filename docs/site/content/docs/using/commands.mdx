Every table on this page is generated from the bot's own alias table, so it
lists what the parser actually accepts rather than what someone remembered to
write down.

Three things hold for every command:

- **The spellings are interchangeable.** `/rules`, `/regras` and `/reglas` reach
  the same handler. The group's language setting changes what the bot *says
  back*, never what it listens for.
- **Accented spellings count.** `/aleatório` and `/reclamação` are separate
  triggers, because that is what a Portuguese keyboard produces.
- **Addressing works.** `/rules@your_bot` behaves like `/rules`, which matters
  in a group running more than one bot. A command aimed at a *different* bot is
  ignored in silence.

<Callout>
**The "In v2" column** is measured, not claimed: it comes from the same test run
as the [progress board](/docs/progress). `Live` means the command's behaviour is
pinned down by scenarios that pass.
</Callout>

## Things without a command

Some of what the bot does has no command at all — it just happens:

- **Link rewriting.** X, TikTok and Bluesky links are reposted in a form that
  actually shows a preview in Telegram.
- **Talking back.** Mention the bot, or reply to it, and it answers. Reply with
  a sticker and it replies with one.
- **Music recognition** on voice notes, where the operator has enabled it.
- **The daily birthday post**, at 00:10 UTC.
- **Joiner screening, sticker limits, media holds.** See
  [Moderation](/docs/using/moderation).

<Callout>
An unrecognised command is **not** silent here: it becomes an image search. That
is v1's catch-all, kept — with the blocklist, the daily limits and the
safe-search rule described under [AI features](/docs/using/ai#any-unknown-command-is-an-image-search).
A command addressed to another bot is still ignored completely.
</Callout>
