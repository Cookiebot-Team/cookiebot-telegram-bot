One page per feature. The header block on each is generated from the migration
spec and the last test run; everything under it is written by whoever ported
the feature — what it does, what a group would notice if it changed, and how to
check it by hand.

<Callout>
This section is the **build** view: one page per unit of porting work, in the
spec's vocabulary. If you run a group and want to know what a command does,
[Using Cookiebot](/docs/using) is the same behaviour written for you.
</Callout>

Status means exactly one thing here:

| | |
|---|---|
| <StatusBadge status="done" /> | Implemented, with at least one scenario executing green |
| <StatusBadge status="partial" /> | Implemented, but the spec is incomplete or scenarios are missing |
| <StatusBadge status="planned" /> | Scheduled in a milestone, not started |
| <StatusBadge status="blocked" /> | Cannot start until something else lands |
